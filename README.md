# RSL-plus

Расширение Visual Studio Code для **RSL / Object RSL** — языка макросов продуктов R-Style Softlab.

Это не подсветка синтаксиса с автодополнением по словам из файла. RSL-plus держит модель всего проекта: он знает, какой `Import` откуда что приносит, какой класс от кого наследуется и куда ведёт каждое имя. Отсюда и переходы через несколько файлов, и Problems, которые видят чужой модуль, и переименование, правящее файлы, которые вы ни разу не открывали.

Проект вырос из расширения [alliluja/RSL](https://github.com/alliluja/RSL) и сохраняет его базовые возможности.

## Навигация по проекту

- **Ctrl+T** — поиск символа по всему проекту. Полный список доступен с первой секунды после запуска: состав файлов сохраняется между сеансами, а не собирается заново.
- **Ctrl+Click / F12** — переход к объявлению. Работает не только для обычных имён, но и там, где имя спрятано в строке:
  - `Import checkaml;` и `Import "checkaml.mac";` — открывается файл модуля;
  - `ExecMacro("Target")`, `ExecMacro2`, `ExecMacroFile("lib.mac", "Target")` — открывается строка объявления, а не начало файла;
  - обработчик, переданный строкой, через `@` или `R2M`.
- **Go to Implementation** и **иерархия типов** — наследники класса по всему проекту, без обхода файлов на каждый запрос. Одноимённые классы из разных модулей не смешиваются.
- **Shift+F12** — все ссылки на символ. Повторный запрос не перечитывает проект: разрешённые ссылки запоминаются и переживают перезапуск.
- **Call Hierarchy** — кто вызывает эту `Macro` и кого вызывает она.
- **F2** — переименование символа во всех точных ссылках.
- **Переименование macro-файла** правит настоящие ссылки на него — имя модуля в `Import` и первый аргумент `ExecMacroFile` — в том числе в файлах, которые никто не открывал. Обычная строка вроде `MsgBox("lib.mac")` не меняется, путь и расширение сохраняются, правки показываются в предпросмотре VS Code.
- **RSL: Выделить текущий блок** и **RSL: Свернуть все Macro в файле**.

## Подсказки при наборе

- Автодополнение локальных, глобальных, импортированных и стандартных имён. После точки предлагаются только члены объекта, включая унаследованные; приватные — лишь внутри своего класса.
- **Auto Import**: имя из ещё не подключённого модуля предлагается вместе с `Import`, который добавится сам. Поиск идёт по всему проекту.
- **Signature Help** с подсветкой активного параметра и типом результата.
- **Hover** с типом, описанием и происхождением символа.
- Тип выводится из результата процедуры: после `rs = execSQLselect(...)` подсказка знает про `rs.MoveNext()` — даже если переменная объявлена без `Var`.
- Подсказки по прикладным модулям платформы — `CommonInter`, `BankInter`, `PaymInter`, `RsbFormsInter` и другим: их классы, процедуры и константы описаны в каталоге расширения. Предлагаются только там, где модуль импортирован, а наследование доходит до стандартных классов.
- **Inlay-подсказки**: имя параметра рядом с аргументом вызова — `Send(document, count: 1, silent: true)`. Выведенный тип переменной — по желанию, настройкой.

## Problems

Проверки идут по мере набора и видят подключённые модули. У каждой есть код, видимый в панели Problems, и уровень.

**Структура и синтаксис.** Незакрытые блоки, лишний `END` и `ELSE`, скобки, незакрытые строки и комментарии, пропущенная `;` между инструкциями, лишняя `;` после заголовка блока, `BREAK`/`CONTINUE` вне цикла, неполный `FOR`, некорректный `ONERROR`, недостижимый код.

**Имена и объявления.** Повторные объявления, использование переменной до объявления, неоднозначные ссылки, неиспользуемые переменные, параметры и `Import`, лишний транзитивный `Import`, обращение к несуществующему полю или методу, необъявленная переменная слева от присваивания.

**Смысл кода.** Присваивание переменной самой себе, сравнение значения с самим собой, заведомо постоянное условие, повторное условие в цепочке `if/elif`, выражение без результата, значение, записанное и перезаписанное без прочтения, лишний аргумент при вызове процедуры своего файла, метод наследника, разошедшийся с базовым числом параметров или передачей по ссылке.

**Совместимость и порядок.** Устаревшие объявления `RECORD` и `ARRAY`, оставленный `DEBUGBREAK`, `Import` внутри `Macro`, присваивание константе, ограничения длины имён и строк, конфликт расширений `Import`.

### Уровни и подавление

Каждую проверку можно поднять до ошибки, опустить до подсказки или выключить:

```jsonc
"rslPlus.diagnostics.rules": {
  "overwritten-value": "information",
  "argument-count": "none"
}
```

Отдельные места гасятся комментарием:

```rsl
// rsl-disable-next-line unused-declaration
Var reserved;

// rsl-disable argument-count
Legacy(1, 2, 3, 4);
// rsl-enable argument-count
```

`rsl-disable-file` выключает проверку на весь файл. Синтаксические ошибки — незакрытый блок, скобка, строка — не гасятся ничем: файл с ними не разбирается, и молчать о них нечестно.

## Действия над кодом

**Quick Fix** для однозначных случаев: удалить `DEBUGBREAK`, лишний `END`/`ELSE`/скобку, повторный или неиспользуемый `Import`, неиспользуемое объявление; добавить пропущенную `;` или `,`, `+` между соседними строками, `end;`; убрать лишнюю точку. Для неизвестного имени — заменить на похожее из этой же области, объявить `Var` или добавить `Import` из модуля, который его экспортирует.

**Organize Imports** — четыре отдельных действия: отсортировать и убрать повторы, удалить неиспользуемые, добавить недостающие, всё сразу. Написание пути сохраняется: `Import "checkaml.mac";` таким и остаётся. Объявление, разложенное по строкам или с комментарием внутри, не собирается заново — из него только вырезается лишнее. Удалять действие отказывается, пока хоть один `Import` файла не разрешился: неизвестный модуль мог объявлять как раз то имя, по которому соседний импорт кажется лишним.

**Рефакторинги:**

- вынести выражение в переменную;
- вынести операторы в процедуру — переменная, в которую они пишут и которую читают дальше, возвращается значением;
- подставить значение переменной;
- заготовка переопределения метода базового класса с точным списком параметров.

Каждый предлагается только там, где перенос доказуемо ничего не меняет. Разрезанный блок, `return` внутри выделения, переменная, читаемая после него, переприсваивание, передача по ссылке — всё это поводы промолчать.

**CodeLens** над `Macro` и `Class` — счёт вхождений имени в этом файле и переходы к References и Call Hierarchy. Выключен по умолчанию.

## Форматирование и ввод

- Форматирование сохраняет строки, SQL, BOM, CRLF и финальный перевод строки. Форматирование выделения не трогает остальной файл.
- Настройки: регистр дописываемых ключевых слов, пробелы вокруг операторов, выравнивание присваиваний, символ и ширина отступа. Отступ берётся из `.editorconfig` проекта, если он есть.
- `Enter` после заголовка блока создаёт тело с отступом и `End;` — по желанию, настройкой; `Shift+Enter` делает это всегда.
- Сниппеты RSL, включая `class`, `classex` и `with`.
- Команды копирования и вставки SQL-запросов.

## Подсветка и структура

- Подсветка синтаксиса RSL, SQL-строк и SQL-блоков `[ ... ]`, вложенные блочные комментарии.
- Семантическая подсветка классов, методов, функций, переменных, параметров и свойств.
- Сворачивание `Macro`, `Class`, `If`, `For`, `While`, `With`, комментариев и SQL-блоков.
- Список символов документа и список известных макрофайлов.
- Файл читается по правилу репозитория: есть BOM — UTF-8, нет BOM — CP866; UTF-16 читается по своему BOM.

## Анализ вне редактора: `rsl-plus check`

Те же проверки, что в редакторе, для выбранных файлов — из терминала, скрипта или CI.

```bash
rsl-plus check --context ./rsmacro rsmacro/retail/payment.mac
```

Корень проекта нужен, чтобы разрешать `Import`: зависимости проверяемых файлов загружаются сами, по цепочке. Проверяются только те файлы, которые вы назвали, — остальной проект служит контекстом.

### Параметры

| Параметр | Что делает |
|---|---|
| `--context <путь>` | корень проекта: по нему разрешаются `Import` |
| `--format text\|jsonl` | формат вывода, по умолчанию `text` |
| `--summary` | только счётчики по файлам |
| `--config <путь>` | файл настроек диагностик |

Вывод для человека идёт в stdout, сведения о самой работе — в stderr, поэтому `> report.txt` не смешивает одно с другим.

```text
rsmacro/retail/payment.mac (3, не разрешён Import: globals)
  12:3-12:18 W overwritten-value — Значение amount перезаписывается, так и не будучи прочитанным
  40:5-40:11 W unused-declaration — Переменная total объявлена, но не используется
  57:9-57:20 I redundant-import — Импорт common уже приходит транзитивно
Итого: файлов 1, сообщений 3 — E:0 W:2 I:1 H:0, неполный контекст: 1
```

Файл, чей контекст собрать не удалось, помечается как неполный, и о каждой недостающей зависимости сказано отдельно: часть выводов по такому файлу недостоверна, и знать об этом важнее, чем получить ровный отчёт.

### Машинный формат

`--format jsonl` даёт по одной записи JSON на строку — `run`, `file`, `diagnostic`, `summary` — со своей версией схемы:

```json
{"schemaVersion":1,"record":"diagnostic","file":"src/payment.mac","severity":"warning","code":"overwritten-value","start":{"line":11,"column":2},"end":{"line":11,"column":17},"message":"..."}
```

Абсолютных путей в записях нет: один и тот же проект, проверенный в двух рабочих каталогах, даёт одинаковый вывод, и его можно сравнивать построчно.

### Коды возврата

Код говорит о работе команды, а не о находках: решение о судьбе изменений принимает тот, кто её вызвал.

| Код | Что означает |
|---|---|
| `0` | команда отработала — сколько бы сообщений она ни нашла |
| `2` | неверные аргументы или непригодный файл настроек |
| `3` | проверяемый файл не читается |
| `4` | внутренний сбой |

Негодный `--config` — отсутствующий, испорченный или с опечаткой в имени правила — останавливает работу кодом `2`: молча пойти со значениями по умолчанию значит незаметно включить или выключить проверки в CI.

Ни Git, ни история, ни сравнение ревизий в команду не входят. Какие файлы проверять, решает вызывающий.

### Настройки для команды

Настройки берутся из `--config` или из `rsl-plus.json` в корне контекста — не из профиля вашего редактора, чтобы результат не зависел от того, кто и как настроил свой VS Code.

```json
{
  "diagnostics": {
    "rules": { "overwritten-value": "error" },
    "shadowedDeclaration": true
  }
}
```

## Стандартные обработчики RS-Bank

Некоторые `Macro` вызываются ядром RS-Bank с позиционным набором параметров. Реализация может использовать только часть, но обязана сохранить позиции до последнего используемого аргумента — поэтому у таких процедур проверяется только неиспользуемый хвост справа, а параметры слева ошибками не помечаются.

Имена постоянно известных обработчиков задаются в корневом [`standard-handlers.json`](standard-handlers.json):

```json
{
  "handlers": ["ExecuteStep", "PostStepAction", "CheckStepAction"]
}
```

Обработчики, переданные в `RunDialog`, `RunScroll`, `AddScroll`, `RunMenu`, `SetOutHandler`, `SetTimer`, `SetHandler` и другие документированные API, определяются автоматически — в строковой форме, через `@` и `R2M`.

## Установка

Из Extensions (`Ctrl+Shift+X`) по имени **RSL-plus** или из командной строки:

```bash
code --install-extension AChumakov.rsl-plus
```

Из собранного VSIX:

```bash
code --install-extension rsl-plus-1.2.2.vsix
```

Команда `rsl-plus` живёт отдельным пакетом npm — расширение из Marketplace её в `PATH` не добавляет. Собрать и поставить пакет из репозитория:

```bash
npm pack
npm install -g ./rsl-plus-1.2.2.tgz
```

## Настройки

Всё лежит в группе `RSL Plus`.

**Анализ проекта**

- `rslPlus.imports.enabled` — анализировать цепочки `Import`;
- `rslPlus.autoImport.enabled` — предлагать Auto Import;
- `rslPlus.analysis.workspaceIndexing` — глубина фоновой индексации;
- `rslPlus.language.dialect` — совместимость RS-Bank или строгий базовый RSL.

**Problems**

- `rslPlus.diagnostics.enabled` — показывать проблемы вообще;
- `rslPlus.diagnostics.rules` — уровень отдельных проверок по коду;
- `rslPlus.diagnostics.<имя>` — включить или выключить проверку;
- `rslPlus.diagnostics.maxProblems` — сколько сообщений выводить на файл.

**Подсказки и подсветка**

- `rslPlus.inlayHints.parameterNames`, `rslPlus.inlayHints.variableTypes`;
- `rslPlus.codeLens.references` — строка над `Macro` и `Class`;
- `rslPlus.semanticHighlighting.maxFileSizeKb`.

**Форматирование и ввод**

- `rslPlus.format.keywordCase`, `spaceAroundOperators`, `alignAssignments`, `indentStyle`, `indentSize`, `useEditorConfig`;
- `rslPlus.editor.completeBlocksOnEnter`.

Команда **RSL: Show Language Server Status** показывает, сколько памяти занимают модели, каталог проекта и записи о ссылках — если сервер ведёт себя не так, как вы ожидаете, начинать стоит оттуда.

## Разработка

Нужны Node.js 18+ и Visual Studio Code 1.90+.

```bash
npm ci
npm test
```

Сборка VSIX и стенды производительности:

```bash
npm run bundle
npx @vscode/vsce package
npm run bench:memory -- --project <каталог с .mac>
npm run bench:cli -- --project <каталог с .mac>
```

`npm test` компилирует client и server и запускает регрессионный набор: lexer, parser, formatter, folding, области видимости, диагностики, навигация, рефакторинги, командная строка, поставка пакета, производительность и память.
