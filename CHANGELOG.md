# Change Log

## RSL-plus 1.1.9

### Архитектура и производительность разбора

* Неоднозначный `Import` (несколько файлов с одинаковым именем) раньше молча пропускался при загрузке зависимостей: символы из такого модуля были недоступны Ctrl+Click и Completion без единого сообщения. Теперь сервер детерминированно выбирает один из кандидатов и продолжает работу; предупреждение `ambiguous-import` по-прежнему отображается в Problems.
* Проверка «актуальна ли версия модуля» была продублирована в анализаторе документа, координаторе диагностик и обработчике настроек с чуть разными условиями. Она сведена к единой проверке в `WorkspaceIndex`, что исключает гонку, при которой Problems могли относиться к уже устаревшей версии файла.
* Полный синтаксический разбор выполняется на основном потоке, а вынос в отдельный worker убран. Замеры показали, что вынос ухудшал именно то, ради чего делался: ответ worker'а — это дерево разбора, где каждый узел несёт свои токены, и его распаковка в основном потоке стоила в 5–12 раз дороже самого разбора на месте (550КБ: 25 мс против 192 мс), добавляя к ответу ещё 100–500 мс. Воспроизвести замер: `npm run bench`.
* Вместо выноса ограничена длина порции очереди разбора: за один проход event loop разбирается один документ, активный — первым. Раньше очередь выгружалась целиком одной цепочкой, и восемь открытых файлов по 300КБ задерживали таймеры и LSP-обмен на 420 мс; теперь задержка не растёт с числом файлов и остаётся на уровне одного разбора.
* Файл из одного очень длинного оператора (свыше ~100 тысяч токенов, примерно от 150КБ) больше не роняет разбор с `RangeError: Maximum call stack size exceeded`.
* Локальные и Workspace Problems запускаются сразу по фактическому завершению разбора вместо периодического опроса с фиксированной задержкой.
* Для больших файлов правка внутри одного слова, числа или строки обновляет lexer точечно, без полного повторного прохода по всему документу; любая более сложная или многострочная правка по-прежнему обрабатывается полным разбором.
* Фоновая индексация workspace (`workspaceIndexing: "full"` и `"workspaceIdle"`) больше не накапливает неограниченное число загруженных внешних модулей — наименее востребованные вытесняются по LRU. Открытые в редакторе документы никогда не вытесняются.
* Поиск модулей, экспортирующих символ, по всему workspace ограничен числом просматриваемых файлов за один запрос; при превышении лимита в лог попадает предупреждение вместо бесконечного обхода.

## RSL-plus 1.1.8

### Стандартная библиотека и IntelliSense
* Добавлен компактный встроенный каталог стандартных процедур и классов RSL: Completion, Signature Help, типы возвращаемых значений и члены стандартных объектов работают без индексации внешних файлов.
* Hover для встроенных символов показывает только сигнатуру и короткое описание — без путей и ссылок на документацию.
* Контекстное Completion предлагает типы RSL, параметры `FILE`/`RECORD` и спецификаторы форматирования выходных форм.
* SPNAME, объявленный внутри `Macro`, корректно получает область всего unit.
* Добавлено точное переименование локальных и проектных символов через `F2`; встроенные символы и опасная смена NAME/SPNAME не переименовываются.

### Проверки совместимости
* Добавлены диагностики ограничений имени, строкового литерала и имени macro-файла, `IMPORT` внутри `MACRO`, присваивания константе и одинаковых имён импортов с разными расширениями.
* Длинный строковый литерал можно безопасно разбить Quick Fix на явную конкатенацию.
* Настройка `rslPlus.language.dialect` разделяет совместимый профиль RS-Bank и строгий базовый RSL; специфичные проверки передачи по ссылке и доступа к `PRIVATE` через `THIS` не создают ложных ошибок в профиле RS-Bank.

### Производительность и тесты
* Smart Enter больше не просматривает остаток большого файла при обычном Enter: поиск закрывающего `END` запускается только для распознанного заголовка и имеет ограниченное окно.
* Каталог встроенных Completion-элементов создаётся один раз и переиспользуется без повторных аллокаций.
* Каталог `.mac` перенесён из VS Code Extension Host в language server. Обход проекта выполняется порциями, уступает интерактивным запросам и больше не блокирует приём Structure/Completion/Hover в UI-процессе.
* Восстановленные неактивные вкладки не лексируются и не разбираются до активации или явного запроса. Активный файл получает Fast Outline и первый слот полного анализа.
* Локальные Problems запускаются сразу после готового AST без повторной задержки; семантическая подсветка уступает интерактивным запросам и ограничивает LRU-кэш четырьмя документами.
* Добавлены регрессионные тесты каталога, профилей, Rename, новых диагностик и Quick Fix, а также измеримые ограничения производительности Smart Enter, Completion и полного анализа файла около 100 КБ.

### Callback-процедуры
* `Ctrl+Click` переходит к процедурам, переданным строкой, через `@` или `R2M`, в документированных API `RunDialog`, `AddScroll`, `RunScroll`, `RunMenu`, `SetOutHandler`, `ProcessTrn`, `Sort`, `SetTimer`, `SetHandler` и `addHandler`.
* Строка в `R2M(object, "Method")` разрешается по типу `object`, поэтому переход ведёт в метод нужного класса.
* Процедуры, переданные как стандартные позиционные обработчики, автоматически получают правило параметров: параметры слева от последнего используемого обязательны и не помечаются как неиспользуемые; предупреждения остаются только для неиспользуемого хвоста.

## RSL-plus 1.1.7

### Архитектура и производительность
* Language server переведён на единую неизменяемую модель `RslSymbol`; старые параллельные модели и временные адаптеры удалены.
* Полная модель открытого документа отделена от компактной модели закрытого импортированного файла. Закрытые модули не удерживают исходный текст, AST и поток токенов.
* `WorkspaceIndex` разделён на каталог файлов, хранилище модулей, граф `Import` и индекс символов. Клиентские команды, инвентаризация workspace и группы LSP-провайдеров вынесены из монолитных точек входа.
* Исправлен квадратичный поиск токенов при извлечении деклараций. Построение дерева символов теперь масштабируется практически линейно и не задерживает большие файлы с тысячами объявлений.
* Метрики `analysis.symbolTree` и `analysis.index` больше не перекрываются: в журнале отдельно видны стоимость построения модели и её регистрация в индексе.

### Семантическая подсветка
* SQL-контекст многострочного блока `[ ... ]` корректно завершается и тогда, когда после `]` расположены аргументы выходной формы. Ключевые слова RSL ниже блока больше не получают SQL-подсветку.
* Класс в позиции объявленного типа разрешается независимо от одноимённых локальных переменных.
* Тип объектной переменной выводится из ближайшего предшествующего присваивания конструктора (`command = RsdCommand(...)`). Вызовы методов после такого присваивания получают стабильную семантическую подсветку.
* Обычная TextMate-подсветка объекта перед точкой теперь охватывает только имя объекта и одинаково работает с латиницей и кириллицей.

### Диагностика и Quick Fix
* Добавлены ошибки для пустых `IMPORT`, `VAR`, `CONST` и `ARRAY`, пустых условий `IF`/`WHILE`, оборванных выражений и неполного заголовка `FOR`.
* Лишняя запятая в конце списка, `BREAK`/`CONTINUE` вне цикла, повторный `ONERROR` и `ONERROR` внутри обычного блока теперь диагностируются до запуска компилятора.
* Quick Fix может добавить пропущенную `;` или `,`, а также удалить лишнюю завершающую запятую.

### Редактор
* `Enter` после полного заголовка `IF`, `WHILE`, `FOR`, `WITH`, `MACRO` или `CLASS` создаёт тело с отступом и закрывающий `End;`. Если `End;` уже есть ниже, он не дублируется.
* Отступ исходной строки при умном `Enter` учитывается один раз: тело смещается на один уровень, а `End;` остаётся на уровне открывающего ключевого слова.
* Умный `Enter` срабатывает и для временно пустых заголовков `IF ()`, `WHILE ()`, `FOR ()` и `WITH ()`, не мешая диагностике напомнить о незаполненном условии.
* Команда `rsl.smartEnter` явно активирует расширение и регистрируется до запуска language server, поэтому `Enter` доступен сразу после открытия RSL-файла.
* Умное завершение блоков можно отключить настройкой `rslPlus.editor.completeBlocksOnEnter`.

### Упаковка
* Из VSIX исключены вложенные служебные файлы `*.patch` и каталог `patches`.

## RSL-plus 1.1.6

### Навигация и автодополнение
* Добавлен поиск символов по уже индексированной части проекта через `Ctrl+T` без нового полного обхода workspace.
* Completion предлагает имена модулей в директивах `Import` и имена файлов в первом строковом параметре `ExecMacroFile`.
* В строковых параметрах `ExecMacro` и `ExecMacro2` предлагаются Macro текущего файла и импортированных модулей; для второго параметра `ExecMacroFile` — Macro выбранного известного файла.
* Исправлена видимость `Private Macro` текущего файла в Completion. Кандидаты ранжируются по области: локальные символы, текущий класс, текущий файл, Import, встроенные символы и Auto Import.
* После двух введённых символов language server заранее фильтрует Completion по prefix, substring и fuzzy-совпадению; импортированные варианты подписаны именем модуля.

### Source Actions
* Добавлен консервативный `Organize Imports`: удаляются только повторные Import с сохранением исходного порядка модулей.
* Добавлен `RSL: Fix All` для безопасных исправлений: повторные `;`, повторные Import и оставленные `DEBUGBREAK`.

### Редактор и диагностика
* Добавлена команда `RSL: Выделить текущий блок`: выбирает ближайший `If`, цикл, `With`, `Macro` или `Class`; повторный вызов расширяет выделение до внешнего блока.
* Предупреждение о неявной конкатенации теперь подчёркивает предыдущий строковый литерал, а Quick Fix добавляет `+` после него в принятом для RSL стиле.
* `ONERROR()` без переменной ошибки распознаётся как допустимая форма обработчика.
* Hover константы показывает её известное значение, в том числе для загруженных импортированных модулей; компактный индекс хранит не более 120 символов инициализатора.

## RSL-plus 1.1.5

### IntelliSense и навигация
* Добавлен Signature Help: при вводе вызова показываются параметры Macro/Method и активный аргумент, включая вложенные вызовы.
* Добавлен Call Hierarchy для просмотра входящих и исходящих вызовов Macro/Method.
* Completion предлагает доступные символы из известных модулей с автоматической вставкой `Import`.
* Quick Fix для неизвестного идентификатора выполняет точный поиск экспортирующего модуля по workspace и добавляет отсутствующий `Import`.
* Передача локальной переменной по ссылке (`@variable`) учитывается как использование и поддерживается навигацией по символу.
* Общесистемные спецпеременные RS-Bank, включая `{oper}`, распознаются без ложной ошибки о неоднозначном Import; их список и типы дополнены по документации.
* Имена `SPNAME` в фигурных скобках поддерживаются как полноценные идентификаторы, в том числе в объявлениях `VAR {oper}` и для произвольных имён вида `{34-23-O}`.
* Верхнеуровневый `END` распознаётся как допустимое завершение макрофайла; код после него помечается как невыполняемый.
* Lexer и parser приведены в соответствие со сводкой синтаксиса RSL для операторов `==`, `!=`, `<=`, `>=`, отдельного оператора `@` и escape-последовательностей `\n`, `\r`, `\t`, `\f`, `\xHH`.
* Уточнён разбор деклараций: `CONST` требует значение, `ARRAY` сохраняет тип элемента, `FILE`/`RECORD` поддерживают `NORMAL`, `BLOB`, `TXT n` и проверяют обязательное имя файла.
* Выходные формы распознают документированные спецификаторы `:i` и `:iv`.
* Повторная точка с запятой (`;;`) отмечается предупреждением с Quick Fix для удаления лишнего символа.

### Редактор
* Добавлено форматирование выделенного диапазона. Форматтер учитывает окружающую структуру, но создаёт изменения только для выбранных строк.
* Форматтер расставляет пробелы вокруг `=` в присваиваниях и после запятых в списках аргументов и объявлений.
* Добавлена команда сворачивания всех Macro в открытом файле.

### Производительность
* Auto Import не запускает обход всего workspace во время обычного Completion. Полный поиск выполняется только при явном вызове Quick Fix и кэшируется.
* Автоматический показ Quick Fix использует только уже известные модули; глубокий поиск по проекту запускается при явном `Ctrl+.` и поддерживает отмену запроса.
* Восстановленные неактивные вкладки строят быстрый Outline без полного AST; полный разбор запускается после активации файла или интерактивного запроса.
* Фоновая индексация приостанавливается во время Completion, Hover, навигации, Outline и других интерактивных запросов.
* Каталог файлов workspace строится после более длинной паузы и отменяется при вводе или переключении вкладки, чтобы не задерживать Structure.
* Семантическая подсветка по умолчанию ограничена файлами до 512 КБ; обычная подсветка синтаксиса продолжает работать без ограничения.

### Настройки
* Настройки приведены к единому пространству `rslPlus.*`, получили понятные булевы переключатели и русские описания режимов.
* Добавлены режим фоновой индексации проекта, переключатель Auto Import и лимит размера для семантической подсветки.
* Удалена неиспользуемая настройка `rsl-plus.programmerName`; старые значения `RSLanguageServer.*` читаются для обратной совместимости.

## RSL-plus 1.1.4

### Производительность
* Ускорено открытие и повторное редактирование RSL-файлов: lexer и parser переиспользуют общие результаты, а частые изменения текста объединяются.
* Folding и Outline появляются без ожидания полного синтаксического разбора и кэшируются для текущей версии файла.
* Диагностика разделена на быстрые локальные проверки и последующий анализ Import-зависимостей.
* Загружается только цепочка Import открытых документов, а закрытые модули хранятся в компактном виде, что снижает потребление памяти на больших проектах.

### Навигация и работа с кодом
* Hover теперь показывает сигнатуру, параметры, тип результата, видимость, базовый класс и документацию символа.
* Добавлена подсветка использований выбранного символа с различием чтения и записи.
* Добавлены переходы к началу и концу текущего блока, а также улучшено расширение выделения для вложенных конструкций.
* Ускорены Go to Definition и Find All References: локальные символы ищутся только внутри своего блока, а для поиска по проекту используется отдельный индекс.

### Parser, Problems и Import
* Добавлено различение SQL-блоков и выходных форм внутри `[ ... ]`.
* Реализован разбор аргументов и спецификаторов форматирования выходных форм с семантической подсветкой и пояснениями в Hover.
* Добавлена диагностика циклических Import с отображением цепочки зависимостей.
* Неоднозначные Import больше не разрешаются случайным выбором файла; устранены ложные сообщения о неоднозначных ссылках и стандартных типах RSL.
* Исправлена поддержка верхнеуровневого `ONERROR`, конструкций `CLASS (BaseClass) ChildClass` и стандартных типов RSL.
* Problems стабильно показывает ошибки активного документа и не заменяет их результатами фонового анализа других файлов.

### Форматирование
* Исправлены отступы внутри верхнеуровневого `ONERROR`.
* Добавлено выравнивание последовательных присваиваний по знаку `=`.

### Надёжность
* Переработана внутренняя организация language server и расширен набор автоматических тестов для parser, диагностики, Import, навигации, форматирования и производительности.
